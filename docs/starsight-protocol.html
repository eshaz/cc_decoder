The StarSight protocol

The byte-level reference for the StarSight Data Transmission Network, carried on a line of the NTSC vertical blanking interval, generated from lib/starsight.py. docs/starsight.md explains it, and docs/research/starsight-sources.md gives its sources.

Packet · Checksums · Commands · Command layouts · Flag bits · Compression

Packet

Byte offsets from the sync. Every number is big endian except the two checks. Times are minutes since 1992-01-01 00:00 GMT.

OffsetBytesFieldNote
01syncAlways 0x2C.
12sizeThe whole packet in bytes, this header and the trailer included, MSB first. At most 0x7F8.
34timeThe minute the packet was sent: minutes since 1992-01-01 GMT, MSB first.
72streamStream id, naming the feed.
92header checkThe low 16 bits of the CRC of bytes 0-8, least significant byte first.
11commandsConcatenated commands, which fill it exactly.
4body checkThe CRC of everything before it, least significant byte first, so that the CRC of the whole packet is zero.

Checksums

Both checks use one CRC: zlib's crc32 with its result inverted. The missing final inversion is what makes the body check come out zero over the whole packet.

PropertyValue
algorithmTable driven reflected CRC-32
polynomial0xEDB88320, the standard IEEE one
initial value0xFFFFFFFF
final inversionnone - the register is returned as it stands
header checkcrc(bytes 0..8) & 0xFFFF == bytes 9-10 read little endian
body checkcrc(the whole packet, its own trailer included) == 0

Station Node Status — type 21

ByteField
0type
1-2length: growing in layout 1; 721 to 743 bytes in layouts 3 and 4
3layout: 1, 3 or 4. Layout 1 places its fields after byte 20 differently
4-5in layouts 3 and 4, a software release: 200, 403 and 405 are known
6-7the stream id the packet headers carry
8-11a Unix time, constant over a session
12-15when the block's contents were assembled, Unix seconds; unset in layout 4
20-23a Unix time, or 0x12CEA600 - 1980-01-01, the zero of a DOS clock - where nothing set it, as every unset time in the block is
58 (layout 1), 48 (layout 3), 48 (layout 4)the station clock when the block was sent, Unix seconds
38-39, 50-51, 40-41 (layout 1)how far through its cycle the station is: a total, how many are done and how many remain, the last two adding up to the first
66-67 (layout 1)minutes since the assembly time. The block grows by two bytes for every eight
the rest of layout 1zero
56-57 (layouts 3 and 4)how many bits of each minute map are in use, 1433 to 1440: it gains one a minute, and when it would pass 1440 both maps turn a byte to the left and it drops by eight, so the bit before it is the current minute
58-237, 238-417two maps of the last day, a bit a minute, the first bit the most significant. What a set bit means is unknown
420-429 (layout 4)an unset time and six zero bytes, which layout 4 inserts, so everything after them sits 10 bytes later than in layout 3
432-459the station's inventory of its own guide: how many it holds of each of 14 tables - regions, channels, titles, descriptions, then the schedules of 10 days from the GMT day of its clock, each counting channels
460-461the stream id again
462the number of tables, 14
463-714a 18 byte record a table of what the station lacks: a count, then the lowest eight missing ids, ascending, zero where there are fewer
721-724from software 403 on, a time at the same local time every day, always the latest one before the clock
the rest of layouts 3 and 4unknown: times at 20-27 and 420-431, a running counter at 30-33, constants at 28-29 and 38-39, values at 40-47, and short counts at 715-732

Compression

A Huffman code of 127 symbols, codes up to 20 bits, Kraft sum exactly 1: 0x00 ends a string, 0x01-0x1F expand to whole words and fragments, and 0x20-0x7E are the printable characters. Theme names are never compressed and region names always are. A News Page's text breaks its lines with 0x1F, which everywhere else expands to 'ur'.
